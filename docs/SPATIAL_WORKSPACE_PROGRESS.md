# Пространственное рабочее пространство: выполнение

Исходная задача целиком сохранена в [SPATIAL_WORKSPACE_OBJECTIVE.md](SPATIAL_WORKSPACE_OBJECTIVE.md). Цель активна, не завершена. Ранее выполненные функции не считаются доказательством соответствия новым требованиям без целевой проверки.

## Текущий этап

Последнее уточнение пользователя переключило приоритет на кинетику карты. Добавлены плавный зум колеса с притяжением к близкому масштабу ветки/подветки/обзора, выбор контекста после pinch, затухающая инерция пустого полотна и прерывание движения новым вводом. Выбранная структурная ветка сохраняет яркость, остальной граф приглушается без изменения координат. Перетаскивание передаёт затухающее движение связанным свободным атомам до трёх переходов; pins и отдельные острова не затрагиваются. Отмена жеста и перенос в состояние восстанавливают вовлечённых соседей. Размещение нового дочернего атома учитывает пересечения существующих рёбер, близкие углы и проходы через узлы.

Проверки этого этапа: 25 unit-тестов в controller/navigation/physics/semantic/placement-routing/zoom-stages; check без ошибок, production build. Chromium: 120 заметок в Ветвях, Молекуле и Созвездиях (обзор, деталь и ограниченное перетаскивание), wheel-контекст и остановка инерции — 4 сценария прошли. Отдельно ранее прошли acceptance/navigation/direct-vault (5 сценариев вместе с wheel). Артефакты: `artifacts/120-*-overview.png`, `artifacts/120-*-detail.png`, `artifacts/zoom-branch-context.png`.

Это не закрывает всю задачу: глобальная маршрутизация уже пересекающихся связей, поведение свободных несвязанных атомов и полноценная проверка pinch на устройстве ещё требуют работы. Ступени сейчас мягко притягивают только к близкому масштабу; toolbar сохраняет обычный шаг. Проверка 120 узлов не заменяет проверку 500/1000 движущихся узлов.

Также завершён следующий шаг выделения Obsidian: назначение Vault paths перенесено из Core в draft policy плагина; bindings мигрируют в `plugin:builtin.obsidian:direct-vaults` без изменения directory handles и ID. Добавлены тесты миграции, коллизий имён и нескольких bindings. Описания ниже про оставшийся naming в Core относятся к предыдущему этапу; адаптеры import/export и UI ещё не перенесены полностью.

Начато фактическое выделение Obsidian из Core. Обработка Markdown/wikilinks (добавление найденных связей и удаление исчезнувших references) перенесена из `Core.saveDraft` в `plugins/obsidian.ts`. Core больше не импортирует parser/resolver из `vault.ts`. Новый публичный `app.atoms.registerDraftPolicy` доступен built-in и community через sandbox RPC; политика получает копию draft/context и возвращает properties/add/remove. Эффекты валидируются и коммитятся одной транзакцией с атомом, после успешного завершения всей цепочки. Runtime проверяет четыре разрешения, убирает registration при disable, не принимает поздний результат выключенного плагина и запрещает вложенные записи из prepare (чтение своих settings/storage разрешено). Документация — `PLUGIN_API.md`.

Проверено: 16 unit-тестов (SQLite rollback/никаких частичных изменений, standalone Core без Markdown policy, enable/disable/re-enable, metadata/manual links сохраняются, неверные targets, permissions, reentrant writes, отключение во время await, прежний Vault round-trip). Check без ошибок/предупреждений; production build. Все 5 Chromium-тестов providers/writing-vault прошли: реальная community policy через Worker, reload/disable, прежние graph providers, отказ без разрешений, Vault editor/wiki/attachments/export и mobile.

Это промежуточный архитектурный этап, не законченный optional Obsidian plugin: `App` пока включает извлечённый `builtin.obsidian` при запуске, сохраняя прежнее поведение приложения. UI-toggle намеренно не добавлен, пока он не сможет выключить всю интеграцию. `Core.saveDraft` ещё назначает Vault source paths; `Vaults.svelte`, `storage/direct-vault.ts` и import/export пока используют Core/Storage напрямую. Следующий шаг — общий import/export и file-access контракт с namespace/migration для существующих файлов и bindings, затем перенос этих адаптеров в plugin, отключение по умолчанию для новых хранилищ и сохранение прежнего включения для существующих. Не объявлять весь блок законченным по одним draft policies.

Close-zoom content теперь отображается отдельным screen-space слоем рядом с атомами: непрерывное раскрытие высоты/opacity с zoom, максимум три фрагмента, приоритет selected Atom. Markdown поддерживает bold/italic/code/links/lists/checkbox через marked + общий sanitizer; сети/HTML-скриптов preview не запускает. Парсинг зависит от content, а не camera frames. Реальная высота измеряется ResizeObserver, размещение учитывает footprints всех узлов/подписей и уже показанных previews. На узком экране используются свободные места сверху/снизу. Слой визуальный/inert, ввод по-прежнему через Atom/editor; preview не меняет world coordinates и не будит physics.

Проверено 17 сентября: check/build, 8 unit-тестов геометрии/размещения/LOD/mobile; Chromium desktop→pan→mobile→zoom-out с Markdown/XSS/координатами, semantic reversal на 120 атомах, stress-preview на 500 и 1000. Сессия старого запуска 40564 отсутствует; результат и артефакты сохранились, после новых правок выполнены новые завершённые запуски. Снимки `artifacts/markdown-500.png`, `artifacts/markdown-1000.png`, `artifacts/markdown-close-mobile.png` просмотрены. На 500 обнаружено и исправлено перекрытие Markdown подписью «Сейчас»: canvas и preview используют общую геометрию заголовка/состояния, размер состояния ограничен 10–13 экранными пикселями. Превью сохраняет предыдущую сторону, пока она свободна, в том числе после измерения высоты и панорамирования. Принудительная смена стороны при нехватке места пока происходит сразу; continuity этого перехода и полный визуальный DoD ещё не закрыты. Stress-проверки фиксируют атомы для доказательства неизменности world coordinates; они не доказывают взаимодействие превью с движущимися плотными графами.

Индикатор сохранения теперь постоянно показывает ✓ при штатных записях; состояние pending и время доступны в раскрываемых подробностях. Спиннер и его CSS удалены, accessible label стабилен. SQLite Worker повторяет только транзакции с SQLITE_BUSY/SQLITE_LOCKED: максимум две дополнительные попытки (40/120 мс) внутри той же очереди. Ошибки ревизии, валидации, I/O не повторяются. Неудачный ROLLBACK прекращает retry. Unit-проверки на настоящем SQLite покрывают откат частично выполненной транзакции без дублей; отдельные проверки статуса покрывают внутренний transient retry, persistent error и восстановление после успешной записи. Это не означает завершение всех требований к очереди позиций/закрытию приложения.

Финальная проверка изменений сохранения: check без ошибок/предупреждений, production/PWA build, 17 целевых unit-тестов. Все четыре Chromium-сценария `search`, `acceptance` (2), `native-backup` завершились успешно: наблюдение DOM подтверждает отсутствие смены иконки/accessible label во время сохранения; проверены drag/pin/state-drop/reload, автосвязи и восстановление настоящей OPFS-копии с отказом на повреждённом импорте.

Продолжать по текущему worktree: в нём уже есть multiple workspaces и staging native restore, поэтому предложенный в Web-сессии патч старого `sqlite.worker.ts` применять нельзя. Исходная спецификация содержит 42 раздела (labels/preview — §15–16); отдельное сохранённое дополнение `SIMPLE_DEFAULTS_OBJECTIVE.md` содержит 63 (labels/preview — §23–24). Не путать их нумерацию. Следующий архитектурный незакрытый блок — optional Obsidian plugin: `Settings.svelte` напрямую включает `Vaults`, а `Core.saveDraft` пока содержит Vault naming и Markdown link reconciliation. Требуется полноценный public import/export и mutation extension path, а не только скрытие UI при выключении.

Backup UI упрощён: полная копия остаётся основным действием, JSON/raw SQLite и локальные снимки доступны в свёрнутом «Дополнительные форматы и снимки». Убрана SQLite/OPFS терминология из обычного описания локального хранилища. Расширенный браузерный тест прошёл для двух реальных OPFS-хранилищ: восстановление второго не переносит каталог из первого, сохраняет оба имени и не меняет данные первого. Архив с верной контрольной суммой и повреждённым SQLite отвергается на staging; после этого корректное восстановление работает. Также прошли legacy JSON recovery, community plugin offline restart, защита от второй вкладки и сравнение движения Molecule/Compact (5 сценариев).

Native backup/restore реализован как один `.phosphored` (SQLite + manifest + SHA-256), имя хранилища + локальный timestamp. Лимит текущего импорта 256 МБ. UI предлагает отдельное подтверждение замены и сохранение текущей копии. Worker импортирует файл в отдельную временную OPFS-базу, проверяет схему/таблицы/данные, мигрирует её, затем переносит все таблицы одной транзакцией. Device-wide каталог хранилищ не импортируется; остальные базы не затрагиваются. После успешной транзакции Worker блокирует последующие запросы до reload, чтобы старый runtime не записал устаревшее состояние. Временный файл удаляется в finally.

Проверки: check/build, 67 unit-тестов, в том числе миграция v1, настройки/plugin_data, сохранение каталога, отказ на повреждённых settings и rollback при ошибке записи. Браузерный сценарий проверяет скачивание настоящей OPFS-копии, повреждённый файл без потери текущих атомов, восстановление координат/metadata/preferences и reload. Старые JSON/raw SQLite инструменты пока остаются доступными; окончательное упрощение backup UI и расширенные проверки нескольких хранилищ/вложений/offline ещё впереди.

Актуальное дополнение пользователя полностью сохранено в `SIMPLE_DEFAULTS_OBJECTIVE.md` (63 раздела). Оно расширяет предыдущую задачу: simple-by-default, optional plugins, безопасное удаление хранилищ и innovation review. Старую матрицу ниже нельзя считать полной проверкой нового DoD.

Новые хранилища запускают только Branch; Templates/types, Daily, Molecule и Compact выключены до явного включения. Выбор фиксируется отдельно для каждого хранилища. Миграция существующих хранилищ сохраняет прежние включения/отключения и старые календарные defaults. Daily после нового включения создаёт один день; год/месяц/недели остаются доступны в настройках. При единственной модели переключатель моделей скрыт. Существующие данные и возможности не удалены. Obsidian/Vault ещё не вынесен в optional plugin; это следующий незакрытый участок, а не выполненный пункт.

Проверено на этом шаге: check без ошибок, production/PWA build, 7 unit-тестов defaults/daily, браузерные сценарии defaults и daily (настройки, повтор, reload, отключение без потери данных). Сценарии сравнения моделей теперь явно включают альтернативные плагины перед выбором.

Модели `builtin.branch`, `builtin.molecule`, `builtin.compact` зарегистрированы отдельными bundled-плагинами через публичный `registerStructuralProvider` + парный `registerPhysicsProvider`. UI выбирает модель из реестра. Структурные расчёты идут в Worker: ветви используют иерархический каркас; молекула расслабляет напряжения всех реальных связей; compact группирует листья около хабов и уплотняет islands. Для остаточных конфликтов подписей используется ближайшее свободное место по footprint. Физические правила различаются: tension-only, двусторонние elastic bonds, ограниченные локальные связи. Старый непарный builtin physics удалён, чтобы не перехватывать выбор модели. Legacy community PhysicsProvider по-прежнему может заменить физику отдельно.

Resume восстанавливает сохранённые мировые позиции без перераскладки. Одиночные изменения обновляют каркас/новые rest lengths, не запускают полный arrange. Перестройка учитывает pin/manual anchors; запрещённые координаты и сдвиг locked атомов отклоняются до применения. Поздние результаты не применяются после drag; изменившаяся ревизия запускает актуальный расчёт. Локальное рабочее множество физики определяется связями вокруг изменений, а не первыми 450 строками базы; отдельный тест покрывает узел 950 из 1000. Минимальный zoom расширен до .035, чтобы большие карты помещались целиком.

Deterministic fixture `stress-fixture.ts`: 100/500/1000, проекты, разные состояния, cycles/cross-links, emoji, длинные названия, контент с tasks и одиночные узлы. В девяти раскладках нет проверяемых пересечений; на текущих замерах compact занимает около 56% площади Branch на 1000 атомах. Все девять браузерных сценариев render/focus/reopen прошли, включая точное сравнение координат после перезапуска. Отдельно прошли перенос на 120 узлах во всех трёх моделях, различия движения на маленькой карте и community structural provider через sandbox API. Последняя адаптация к anchors дополнительно проверяется перед завершением этапа.

Текущий визуальный отчёт: `artifacts/physics-comparison.html`, генератор `scripts/build-physics-report.mjs`, 18 снимков overview/local для трёх размеров. Это не закрывает весь DoD: на 1000 ещё не проверены все операции добавления/удаления Links, Tasks/Templates, branch import/export, rich Markdown preview и окончательный routing. Цель остаётся активной.

Semantic renderer теперь хранит визуальные состояния узлов и links отдельно от GraphModel/physics. Дети появляются из текущего положения родительского кластера; при обратном переходе сходятся к центру. Opacity/радиус/позиции продолжаются из текущего кадра при развороте, удалённые представления исчезают после затухания. Концы links интерполируются при изменении агрегированных endpoints. Hit-testing использует только живую целевую проекцию с достаточной opacity. Семантические пороги .42/.56 образуют hysteresis; камера по-прежнему не меняет мировые координаты. Мелкие точки и тонкие связи свёрнутых ветвей затухают вместе с родительским представлением. Reduced motion немедленно применяет конечное состояние.

Измерение подписей использует ограниченные кеши (4000 записей), реальные canvas metrics и Intl.Segmenter для целых grapheme clusters. Длинные слова/emoji переносятся без разрезания ZWJ-последовательностей; многоточие учитывается в ширине. Размер экранной подписи округлён до четверти пикселя, чтобы непрерывный zoom не создавал новый ключ measurement на каждый кадр.

Проверки этого этапа: check/build, 51 unit-тест; браузерные сценарии branch/contact/navigation/semantic проходят. `semantic.spec.ts` проверяет 120 закреплённых атомов, разворот зума, окончание transitions и неизменность x/y. Снимки: `artifacts/semantic-overview.png`, `artifacts/semantic-detail.png`. Это ещё не проверка всей иерархии world→regions→clusters на 1000 атомах. Следующий этап — полноценные структурные providers Branch/Molecule/Compact и их масштабные fixtures.

Добавлены `graph/navigation.ts` и `graph/neighborhood.ts`: плавный перелёт камеры через мировые центры с временным отдалением на длинных маршрутах; прерывание pointer/wheel; browser Back/Forward хранит focus/lens/camera в history state, изолированном по адресу хранилища. Закрытие редактора восстанавливает контекст, из которого он был открыт. Browser Back при открытом редакторе меняет фон/контекст возврата, сохраняя несохранённый текст в открытом редакторе; окончательный immersive lifecycle ещё не завершён.

Local attention учитывает входящие/исходящие связи, взвешенную дистанцию до четырёх переходов, значимость узлов, общих соседей и переход через крупный hub. Количество детальных узлов ограничено; несколько пространственных соседей оставлены как ориентиры. Остальные узлы остаются на карте с меньшей opacity, подписи скрываются. Attention интерполируется в renderer, world state не меняется. Окончательная работа с границами ветвей, zoom ranges, объединёнными links и semantic crossfade остаётся впереди.

Проверено для этого этапа: check без ошибок/предупреждений, сборка, 47 unit-тестов; браузерный сценарий search A→B→Back→Forward→editor→close и сохранения world coordinates. Сценарии ежедневных заметок и MVP/внешнего плагина тоже проходят. Стресс 500/1000 и полный визуальный DoD пока не доказаны.

Выделен builtin.daily, добавлены независимые настройки года/месяца/недель месяца и формат названия дня. Общая страница плагинов и декларативные boolean/text настройки доступны встроенным и внешним плагинам с разрешением settings. Повторная команда сохраняет существующий день и его иерархию. Все данные остаются Atom/Link.

Проверено: svelte-check, production build, 2 unit-теста (8 комбинаций уровней, повтор, формат, порядок начального размещения), браузерный сценарий создания/повтора/перезагрузки/отключения без удаления данных.

Остаётся у Daily: устойчивое календарное размещение при смене physics/layout, общие форматы имён контейнеров, проверка большого календаря. Начальные позиции упорядочены, но это не доказывает стабильный порядок после любой перестройки.

Следующий архитектурный этап: world state/navigation/local context и структурные provider contracts. Затем разные Branch/Molecule/Compact реализации с fixtures 100/500/1000. Interop, native restore, Templates/Tasks и остальные требования остаются в полном объёме. Не переписывать весь репозиторий; читать затронутую подсистему перед каждым этапом.
