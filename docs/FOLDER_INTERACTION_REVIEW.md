# Follow-up to 0.6.0 — folder and gesture cleanup

Follow-up to 9642e02. Folder membership, gestures and compact controls share the existing local data model.

- A drop on a folder adds the raw selection unless every selected atom already belongs to it. In that case it removes membership. Matching folders show a cross and a removal tint during drag; the hover caption states the action. Mixed selections are added as a whole. The All slot also offers explicit removal from the focused folder, or all folders when no folder is focused. Folder removal never deletes atom content or links.
- Definitions now accept a bounded optional `excluded` list. It overrides inherited and persisted memberships, and survives reload/import. Re-adding clears exclusions atomically in the definition owner update. Descendants whose only membership route passes through an excluded ancestor can also leave the folder; explicit memberships remain independent. This retains the existing branch-based inference model; exclusion does not delete any notes or links.
- A secondary folder panel remains available in the atom menu, including raw multi-selection. Unrelated community context actions remain available there; built-in duplicate actions are omitted from the main menu.
- Holding an atom/selection exposes a temporary state tray with vector icons for Now/Field/Archive. Dropping restores the drag's original coordinates and changes state for the raw selection. Pinch/cancel/release closes the tray. Standard context actions still open on stationary release.
- Daily commands receive optional public `CommandContext.folderId`. Creation passes through contextual placement and an atomic parent link, with explicit current-folder metadata. Existing daily text remains untouched. Calendar containers no longer force a contextual note into distant calendar coordinates.
- Importance is saved together with appearance, rather than discarding unsaved appearance on importance change. Obsolete postponement/group-move actions and per-card board state selectors are removed. Legacy paused notes can still resume.
- Muted in-app color swatches replace the platform folder picker; strip tabs use rounded clipping, hidden scrollbars and item snapping. Folder boundaries are quieter; small folder/cluster framing caps zoom at 0.85. Relationship endpoints retain pointer hit areas with smaller visible rings when zoomed out. Tap effects are quieter, hold effects remain visible. Slider track has one container and tick-aligned feedback.
- Public atom updates now honor a caller's revision to reject stale metadata writes.

Validation: production Vite build and normal Svelte/TypeScript diagnostics pass with no warnings; 243 unit tests pass. Chromium covers six new folder/gesture scenarios and four navigation regressions, alongside the affected board, gesture and legacy-resume scenarios. Seven targeted Firefox scenarios pass, including daily contextual creation and zoom placement. Headless checks are not a physical Nothing Phone 1 performance measurement. Encryption and P2P pairing are explicitly deferred by the user; this release does not implement them or claim encrypted storage.

Commands now wait for the transient menu's history entry to be removed before initiating navigation. The menu trigger remains disabled for the command's duration, preventing immediate reopening from racing a pending history back. This fixes daily creation followed immediately by opening Settings. Community context actions remain separate from general commands.
