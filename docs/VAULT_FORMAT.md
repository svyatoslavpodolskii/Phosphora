# Markdown и Obsidian

В настройках доступны импорт папки (`webkitdirectory`), импорт ZIP и экспорт Markdown ZIP. Папка сохраняет пути относительно выбранного корня. ZIP сохраняет пути записей архива. Импорт добавляет файлы в текущее независимое хранилище; одинаковые пути из разных импортов не перезаписывают друг друга. Новое независимое хранилище создаётся через переключатель слева в шапке. При экспорте можно выбрать отдельное хранилище или всё текущее хранилище.

Markdown заметки становятся атомами. Их текст хранится без YAML-заголовка, алиасы читаются через YAML parser. Исходные байты всех файлов, включая Markdown, `.obsidian`, бинарные вложения и неизвестные форматы, сохраняются в SQLite `settings`: файлы разбиты на блоки по 3 МиБ, закодированные base64. Каталог `vaults` связывает пути с блоками и ID атомов. Одна транзакция фиксирует атомы, связи, файлы и каталог. Новая схема базы не требуется. Полный SQLite export включает все файлы.

Неизменённые заметки экспортируются исходными байтами. При редактировании текста сохраняется исходный YAML, включая комментарии, неизвестные свойства и форматирование. Изменение алиасов обновляет YAML через Document API. Некорректный YAML при попытке изменить алиасы вызывает ошибку экспорта, а не потерю свойств. UTF-8 BOM и CRLF сохраняются у неизменённых файлов. Удалённые атомы не возвращаются как заметки при экспорте; исходные файлы остаются доступны для восстановления атома из локального снимка.

Wiki links и Markdown links создают связи между разрешёнными заметками. Учитываются относительные пути, расширение `.md`, anchors и aliases. Неоднозначное короткое имя не связывается с произвольной заметкой. Содержимое code blocks сохраняется. В просмотре внутренние ссылки открывают заметку, локальные растровые изображения отображаются; прочие вложения доступны для скачивания. Внешние изображения не загружаются автоматически.

Связи, созданные на карте без текстовой ссылки, экспортируются обычными wiki links в конце заметки. Служебный файл `.phosphored/graph.json` сохраняет позиции, состояния, типы, оформление, свойства и отношения для обратного импорта. Он не нужен Obsidian для работы с заметками. При совпадении с чужим файлом выбирается свободное служебное имя.

Импорт ограничен 30 000 файлами и 512 МиБ распакованных данных; существующая модель атома ограничивает текст одной заметки 2 миллионами символов. Превышение лимита, некорректный UTF-8, повторяющиеся или небезопасные пути прекращают импорт с ошибкой без изменения карты. Это перенос файлов, а не фоновая синхронизация с папкой на диске. Код из `.obsidian` хранится как данные и не исполняется. При объединении нескольких источников wiki links переписываются с учётом их отдельных путей; содержимое code blocks не переписывается.

Совместимость форматов сверена с документацией [Obsidian о хранении данных](https://obsidian.md/help/data-storage), [внутренних ссылках](https://obsidian.md/help/Linking%20notes%20and%20files/Internal%20links) и [свойствах](https://obsidian.md/help/Editing%2Band%2Bformatting/Properties). Обновление YAML использует [Document API библиотеки yaml](https://eemeli.org/yaml/).
